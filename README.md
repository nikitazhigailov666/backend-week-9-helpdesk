# API заявок в техподдержку

Учебный проект по Node.js и Express.js. Выполнил Жигайлов Никита Николаевич.

Сервис принимает заявки, показывает список, фильтрует его по статусу, позволяет менять статус и удалять заявки. Данные хранятся в памяти процесса и сбрасываются при перезапуске.

## Запуск и проверка

Требуется Node.js 24. В корне проекта выполните:

```sh
npm ci
npm start
```

API доступен по http://127.0.0.1:3002. Проверка сервера — GET /health. Команда npm test выполняет интеграционные тесты на отдельном экземпляре приложения со случайным свободным портом.

Импортируйте Helpdesk.postman_collection.json в Postman. Запустите коллекцию целиком через Run collection. Второй запрос сохраняет id, следующие используют его для чтения, изменения и удаления заявки. Для запуска из терминала при работающем API выполните npx --yes newman run Helpdesk.postman_collection.json.

## Маршруты

| Метод и путь | Назначение | Статусы |
|---|---|---|
| GET /health | Проверить доступность | 200 |
| GET /api/tickets | Получить список, опционально с ?status=closed | 200, 400 |
| POST /api/tickets | Создать заявку из JSON с полем title | 201, 400 |
| GET /api/tickets/:id | Получить заявку | 200, 404 |
| PATCH /api/tickets/:id | Изменить status | 200, 400, 404 |
| DELETE /api/tickets/:id | Удалить заявку | 204, 404 |

Допустимые статусы — open, in_progress, closed. Заголовок содержит от 1 до 120 символов. Примеры тел запросов — {"title":"Не работает Wi-Fi"} и {"status":"closed"}.

## Структура сервера

- src/server.js запускает HTTP-сервер. PORT позволяет изменить порт.
- src/app.js создаёт Express-приложение, подключает middleware, health-маршрут и маршрутизатор заявок.
- src/tickets.js содержит Express Router, проверки полей и хранилище Map.
- test/api.test.js проверяет реальные HTTP-ответы на тестовом экземпляре приложения.

Порядок обработки запроса имеет значение. Сначала middleware выставляет X-Request-Id, затем express.json разбирает тело запроса. Маршрутизатор выбирает обработчик по методу и пути. Для маршрутов с :id функция router.param находит заявку и передаёт её обработчику. После маршрутов обычный middleware отвечает 404 для неизвестного пути. Последний middleware принимает четыре аргумента и обрабатывает ошибки, в том числе некорректный JSON и превышение лимита в 16 КБ.

## Проверка через GitHub

В корне репозитория должен находиться package.json. Файл .github/workflows/test.yml запускает npm ci и npm test на Node.js 24 при push и pull request. Результат появляется во вкладке Actions.

## План защиты

1. Показать server.js, app.js и tickets.js. Объяснить, почему запуск сервера отделён от создания приложения.
2. Проследить путь POST-запроса от middleware до роутера. Показать X-Request-Id в ответе.
3. Запустить коллекцию в Postman. Показать создание заявки с 201, изменение статуса и фильтр, удаление с 204, повторный GET с 404 и отклонение пустого заголовка с 400.
4. Показать тесты и описать ограничение хранилища в памяти процесса.
